1. Overview

            
TheBlockMaster is a single-origin, offline-first web app for inspecting elliptic-curve keys, HD wallets, hashes, and Monero addresses. Everything runs in the browser with deterministic BigInt / ed25519 math — no backend, no AI claim to break ECDLP.

            
    
              
  • Home — centered search that routes into EQIR / BIP / Brainwallet by input type.
    • 
              
  • EQIR Lab — secp256k1 Double-and-Add research lab (BTC + ETH/BSC derived).
    • 
              
  • BIP39 / BIP32 — mnemonic & HD derivation (Ian Coleman / bip32.org lineage).
    • 
              
  • Brainwallet — passphrase → SHA-256 → key (educational).
    • 
              
  • Calculators — hash / Base58 / hex-dec / BigInt tools.
    • 
              
  • XMR — Monero EQIR lab (ed25519 spend/view/address/scalar).
    • 
              
  • Docs — this page.
    •

4. EQIR Lab (BTC · ETH/BSC)

            
Simple · Advanced

            
Simple (#lab/simple) shows private → public keys plus BTC and ETH/BSC addresses together — no chain split, no research modules or sidebars. Advanced (#lab/btc / #lab/eth) is the full lab with Double-and-Add, STATE, and modules.

            
Chain subtabs

            
BTC shows WIF, hash160, P2PKH / P2SH-P2WPKH / P2WPKH / Taproot. ETH / BSC shows the same secp256k1 key as 0x with etherscan / bscscan explorers. Shared pubkey panel is always visible.

            
Modules

            
    
              
  • Curve — secp256k1 SPEC fields.
    • 
              
  • Scalar — private → public + full Double-and-Add chain (MSB-first).
    • 
              
  • Reverse — public seed + ↑ Half / Half(R−G) when indices known (not an ECDLP solver).
    • 
              
  • Kangaroo — Pollard lambda sandbox (small bits in-browser).
    • 
              
  • XOR — reversible scalar/bit transforms + fingerprint cloud.
    • 
              
  • QI Walk — classical amplitude simulation over kangaroo jumps (no quantum speedup claim).
    • 
              
  • Compare — side-by-side trajectory metrics.
    • 
              
  • ⧉ STATE — export shared STATE JSON from the current chain.
    • 
            

            
Input & chain

            
Enter private hex or public (02/03/04). Priv → Pub + chain builds the operation list. seq pub → pk accepts contiguous 2P / 2P+G steps. build #1–70+#75 loads the Δ·G puzzle path when the JSON asset is present.

            
Sidebars

            
Left: relations (collisions/repeats) + private-key history (localStorage). Right: pins + Base58/SHA/RIPEMD/calc/hex tools accordion.

          


          

            
5. BIP39 & BIP32

            
BIP39

            
Generate 12–24 English words, optional BIP39 passphrase, PBKDF2 seed, BIP32 root xprv/xpub, path presets (BIP44/49/84/ETH), address table with → EQIR.

            
Footer credit: IanColeman (MIT lineage).

            
BIP32

            
Root source:

            
    
              
  • Extended key — paste xprv/xpub.
    • 
              
  • Passphrase — SHA-256 × rounds (default 50k, bip32.org-style) or PBKDF2-HMAC-SHA512 → master seed/xprv, then derive.
    • 
            

            
Derivation mode: custom path or account (k) + index (i) as m/k'/0/i. Send child keys to EQIR BTC or ETH/BSC.

          


          

            
6. Brainwallet & Calculators

            
Brainwallet hashes a passphrase (SHA-256 or hash256) into a secp256k1 private key and shows WIF / BTC / ETH. Unsafe for real funds — lab only.

            
Calculators expose the same primitives as the EQIR tools sidebar in a full-page layout: hashes, Base58(check), hex↔utf8/XOR, hex↔decimal (incl. 32-byte pad), BigInt + / − / × / ÷ / mod / pow / inv / gcd.

          


          

            
7. XMR EQIR Lab

            
Monero uses ed25519 (via noble-ed25519, MIT). Modules:

            
    
              
  • Keys — random/paste spend → view = sc_reduce32(Keccak(spend)) → pubs → standard address (main/stage/test).
    • 
              
  • Scalar — MSB-first Double-and-Add trace on ed25519.
    • 
              
  • Curve — ed25519 parameters.
    • 
              
  • Address — decode / checksum / re-encode Monero base58 blocks.
    • 
              
  • Kangaroo / XOR — small-bit educational sandboxes.
    • 
            

          


          

            
8. Shared STATE (EQIR contract)

            
EQIR modules share a STATE object per chain step:

            
STATE
 ├── Point X / Y / compressed
 ├── Scalar / bits / bitIndex
 ├── Previous operation
 ├── Double count / Add count
 ├── XOR trail[]
 ├── Kangaroo { a, b, herd, dist, jumpIdx }
 └── fingerprint (sha256 prefix)

            
Use ⧉ STATE in EQIR to download eqir-states.json. The preview panel shows a live slice of the same JSON.

            
App-level shared snapshot for agents is published to localStorage["tbm-shared-state"] and window.TheBlockMaster (see next section).

          


          

            
9. Connect an AI agent (shared STATE + agent browsers)

            
TheBlockMaster exposes a first-class bridge so Cursor Agent, Playwright, Chrome DevTools, or any agent browser can read/write lab state without a server.


            
9.1 Global API

            
In the page console or via Runtime.evaluate / agent browser JS:

            
// snapshot (includes secrets by default — treat as sensitive)
TheBlockMaster.getSnapshot()
TheBlockMaster.getSnapshot({ includeSecrets: false })

// publish to localStorage + BroadcastChannel + events
TheBlockMaster.publish()

// navigate + fill
TheBlockMaster.goto('lab', { chain: 'btc' })
TheBlockMaster.setPriv('1')
TheBlockMaster.setPub('02…')
TheBlockMaster.applySnapshot({
  page: 'bip39',
  inputs: { bip39Phrase: 'abandon abandon … about' }
})

// subscribe
TheBlockMaster.subscribe((snap) => console.log(snap.page, snap.derived))

            
Aliases: window.__tbmAgent === window.TheBlockMaster.

9.3 postMessage protocol (iframe / extension)

            
// Agent → TheBlockMaster
iframe.contentWindow.postMessage({
  target: 'theblockmaster',
  type: 'getSnapshot',
  includeSecrets: true,
  id: '1'
}, '*')

iframe.contentWindow.postMessage({
  target: 'theblockmaster',
  type: 'applySnapshot',
  id: '2',
  snapshot: { page: 'xmr', inputs: { xmrSpend: '…' } }
}, '*')

iframe.contentWindow.postMessage({
  target: 'theblockmaster',
  type: 'goto',
  page: 'calculators'
}, '*')

// TheBlockMaster → Agent
// { source:'theblockmaster', type:'snapshot'|'applied', id, snapshot }


            
9.4 Agent browser playbook (Cursor / CDP / Playwright)

            
    
              
  1. Start the static server on :8770.
    2. 
              
  2. Open or navigate the agent browser to http://127.0.0.1:8770/#lab/btc.
    3. 
              
  3. Evaluate TheBlockMaster.getSnapshot() to read page, chain, inputs, derived addresses, STATE preview.
    4. 
              
  4. To drive the lab: TheBlockMaster.applySnapshot({…}) or fill DOM fields (#priv, #pub, #bip39-phrase, #xmr-spend, …) then click the existing buttons.
    5. 
              
  5. Prefer hash routes for deep links (#bip32, #xmr) so the agent can bookmark steps.
    6. 
              
  6. For multi-step research, call TheBlockMaster.publish() after each action so localStorage['tbm-shared-state'] stays current for other agent turns.
    7. 
            

            
// Playwright example
await page.goto('http://127.0.0.1:8770/#lab/btc')
await page.waitForFunction(() => window.TheBlockMaster)
await page.evaluate(() => TheBlockMaster.setPriv('1'))
await page.click('#btn-fwd')
const snap = await page.evaluate(() => TheBlockMaster.publish())
console.log(snap.derived)


            
9.5 Suggested agent workflow

            
    
              
  1. Orient — getSnapshot() or open #docs.
    2. 
              
  2. Choose surface — EQIR for secp256k1 trails, BIP39/32 for HD, XMR for Monero, Calculators for hashes.
    3. 
              
  3. Write inputs via API or DOM; never exfiltrate secrets to remote tools unless the user asked.
    4. 
              
  4. Run UI actions (Priv→Pub, Derive, Decode) the same way a human would.
    5. 
              
  5. Read STATE — export JSON, preview panel, or publish() snapshot for the next agent step.
    6.

11. Security & limits

            
    
              
  • All crypto is local. Balance lookups (EQIR derived panel) are the only optional network calls.
    • 
              
  • Brainwallet / BIP32 passphrase modes are educational — low entropy is crackable.
    • 
              
  • Kangaroo / QI modules are sandboxes for small bit widths, not puzzle solvers.
    • 
              
  • Agent snapshots may contain private keys. Use includeSecrets: false when sharing logs.
    • 
              
  • TheBlockMaster itself is GPL-3.0 — see LICENSE in the repo. Third-party dependencies keep their own notices (Ian Coleman lineage MIT, noble-ed25519 MIT, bip32.org public-domain lineage) in UI footers.
    •
